We will fix this by creating a dedicated Spatial Dimension table (`gmap_places`) using a hotfix script, avoiding the need to re-run the heavy 167,000-row NLP pipeline.
So act as a Senior Data Engineer. 
We discovered an architectural anomaly from our earlier ETL phase (Lesson 6): our `gmap_reviews_enriched` table contains 167,001 rows of NLP-enriched reviews, but lacks the actual spatial coordinates (`latitude`, `longitude`, `geom`) because the spatial join was missed before pushing to PostGIS
Architectural Decision: Instead of copying the same coordinates 167,000 times into the reviews table (bad practice), we will create a proper relational Spatial Dimension table called `gmap_places`
Please implement the following Hotfix:
	1. Create a script named src/agent/hotfix_gmap_spatial.py.
	2. Data Extraction: Use the kagglehub library to programmatically download the raw Google Maps dataset (kagglehub.dataset_download("betianalopezandueza/gmap-state-florida")). Locate the .csv file in the cache and load it. Extract the unique gmap_ids and their corresponding name_x.
	3. Geocoding Transformation: Since this specific dataset lacks native coordinates, we must geocode them! Filter down to unique places only (approx. 6,000 places). Use the official googlemaps Python library, authenticating with the GCP_API_KEY from our .env file, to geocode the name_x string into latitude and longitude. Use GeoPandas to convert the resolved lat/long into a spatial column: Geometry('POINT', srid=4326).
	4. Load (PostGIS): Use our existing DBEngine to push this lightweight GeoDataFrame to PostGIS into a new table named gmap_places.
	5. Validation Step (__main__ block): In hotfix_gmap_spatial.py, add an if __name__ == '__main__': block. When run directly, it must execute the ETL hotfix, then run a raw SQL SELECT COUNT(*) on the new gmap_places table and print the total unique places loaded.
	6. Spatial Data Validation: Add a second validation query in the __main__ block that executes SELECT COUNT(*) FROM gmap_places WHERE ST_SRID(geom) != 4326 OR geom IS NULL;. It must assert that this returns 0, proving that every single place was correctly inserted with valid, non-null spatial coordinates.
	7. Unit Tests: Create tests/unit/test_hotfix_gmap.py. Write a test that queries the gmap_places table to ensure the geom column is recognized as a valid PostGIS geometry (e.g., asserting ST_SRID(geom) = 4326 is true for at least one row).
	8. Implementation Plan Review: Acknowledge that moving forward, all GeoAI spatial tools in src/agent/tools/spatial_tools.py that need to search for reviews geographically must now use a relational join: SELECT * FROM gmap_reviews_enriched r JOIN gmap_places p ON r.gmap_id = p.gmap_id.
